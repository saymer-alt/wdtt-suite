# WDTT Suite — Android, Keenetic и VPS

**WDTT Suite** развивает транспорт WDTT (WireGuard через DTLS/TURN) и инструменты qWDTT. В репозитории есть Android-клиент, сервер WDTT и отдельные экспериментальные сборки Go-клиента для Keenetic с Entware. Это форк, а не официальный релиз оригинального WDTT.

> **Статус на 21 октября 2026:** базовая ветка `awg-client` содержит главным образом Android-клиент и сервер. Текущий Keenetic-клиент разработан в **отдельных Draft PR**, не слит с базовой веткой, не объявлен стабильным и не включён в KAS. Испытания и бинарники ниже относятся строго к закреплённому тестовому исходнику.

## Принцип работы

```text
Android / Keenetic                  VK TURN                     Ваш WDTT-сервер
WireGuard или локальный SOCKS5
       │
       └─ WG → DTLS/RTP + WRAP ──────── TURN relay ────────────────> VPS → интернет
```

Клиент получает временные TURN-учётные данные, устанавливает защищённое соединение и передаёт трафик WireGuard через сервер. В зависимости от платформы трафик можно передавать через Android VPN или локальный SOCKS5. Возможность работать через конкретного оператора связи, ограничения TURN или доступность VK зависят от среды и должны проверяться отдельно. **Это не гарантия обхода любой блокировки и не обещание отсутствия утечек.**

## Что проверено на реальном Keenetic

**Устройство:** Netcraze NC-4210 (ARM64), Entware. **Версия:** объединённый экспериментальный клиент PR #34, исходный commit `b62bd1a7987713e8eb5ca468ef764d1c0ecac474`.

| Показатель | Результат реального короткого теста |
|---|---|
| Анонимный профиль с 18 воркерами и двумя VK-хешами (**18/2**) | 18 одновременно зарегистрированных воркеров: группа 1 — 9, группа 2 — 9 |
| Получение конфигурации | `CONFIG_READY` |
| SOCKS5 | `127.0.0.1:1081` принимает подключения |
| HTTPS через SOCKS5 | HTTP 200, одна завершённая TCP-сессия, передано 1 859 Б / получено 6 436 Б |
| Ошибки получения TURN-учётных данных / события квоты | 0 / 0 в этом тесте |
| Максимальная RSS процесса | 26 924 КиБ (≈26,29 МиБ) |
| Завершение теста | Клиент остановлен тестовым скриптом; SOCKS-порт закрыт |

Это около **70 секунд работы**, а не полный 120-секундный прогон: скрипт выполняет проверки после начальной паузы и останавливает свой процесс. `tcp_relay_context_canceled=1` отражает отмену контекста при остановке скрипта; ошибки передачи и тайм-ауты копирования равны нулю.

**Пока не доказано на реальном оборудовании:** успешная работа профиля `18/1` с одним хешем, коротких паролей чужих серверов, SOCKS5 UDP ASSOCIATE, непрерывная работа 30 минут, автоматическое завершение с кодом 75, отсутствие обходных маршрутов и стабильная память под длительной нагрузкой. Снижение RSS в сравнении с более ранней версией пока не подтверждено контролируемыми измерениями.

## Тестовая ARM64-сборка для Keenetic

Бинарник доступен только как **экспериментальный prerelease**. Он не входит в обычные Android-релизы и не заменяет штатную прошивку/KAS/Entware.

- [Загрузка PR #34, ARM64, SHA256 и тестовый скрипт](https://github.com/saymer-alt/wdtt-suite/releases/tag/wdtt-owner-nc4210-pr34-20261021-b62bd1a79877)
- **SHA256 `wt-client-linux-arm64`:** `afcaa09a889260d6c3bf661396640f1e3d2ba677a2743b98eed71f9aaafe8182`
- **Исходный код:** commit `b62bd1a7987713e8eb5ca468ef764d1c0ecac474`

Пример загрузки **без WinSCP** с GitHub по HTTPS, если уже создан приватный каталог и на устройство вручную подготовлен отдельный конфиг:

```sh
umask 077
mkdir -p /opt/wdtt-field-candidate
chmod 700 /opt/wdtt-field-candidate
cd /opt/wdtt-field-candidate || exit 1

BASE="https://github.com/saymer-alt/wdtt-suite/releases/download/wdtt-owner-nc4210-pr34-20261021-b62bd1a79877"
curl -fL --retry 2 -o wt-client-linux-arm64 "$BASE/wt-client-linux-arm64" &&
curl -fL --retry 2 -o SHA256SUMS "$BASE/SHA256SUMS" &&
curl -fL --retry 2 -o test-120.sh "$BASE/test-120.sh" &&
chmod 700 wt-client-linux-arm64 test-120.sh &&
sha256sum -c SHA256SUMS &&
sh -n test-120.sh
```

**Не запускайте `test-120.sh` без отдельного приватного `config.json`** с правами `0600`, собственной разрешённой конфигурации и предварительной проверки, что порт `127.0.0.1:1081` свободен. Скрипт содержит независимый сторожевой таймер до 120 секунд; не надо трактовать его как доказательство 120 секунд непрерывной работы. Эксперимент проводите только в отдельном каталоге, не заменяя работающий клиент. Ключи, пароли и полные `wdtt://`-ссылки не публикуйте в логах, GitHub Issues и CI.

## Совместимость и незаконченные задачи

Экспериментальный кандидат отдельно проверяется на синтетических профилях `9/1`, `16/1`, `18/1`, `18/2`, на формате `qwdtt://config?... ` и на классическом `wdtt://IP:DTLS:WG:LOCAL:PASSWORD:HASH`. Для классических ссылок 12–15 буквенно-цифровых символов разрешены только при специальном явном выборе лабораторного режима; обычное ограничение 16 символов сохраняется. Поддержка `wdtt://base64(JSON)` из отдельных серверных панелей и непрозрачных ссылок RtpTun **не заявляется**.

Инженерный план: подтвердить `18/1` реальным разрешённым ключом; проверить отдельный UDP-тракт; провести сравнимые длительные испытания 18 зарегистрированных воркеров; только после этого оптимизировать RAM, сохраняя функциональную совместимость и безопасные ограничения.
